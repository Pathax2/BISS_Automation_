The recovery ladder

Introduced in the modernised Selenium framework and carried into Playwright. The legacy suite had none.

1
Smart waitspoll for readiness, never sleep
2
Dropdown self-healmat-select, then overlay fallback
3
Expired-login recoverymark the agent, pick a fresh pair
4
Blacklist and re-fetchskip a consumed herd, draw the next
5
Scenario retryreplay on a known transient error
6
Soft assertionscollect non-critical misses together
One locator, the document-type dropdown, accounts for 66 of the 128 fallbacks. Fixing that single key removes half of them.

How to read these numbers

  • Test cases are not the same size. A legacy test case is one short scenario. A Playwright test case is an end-to-end journey that chains many of them, which is why 25 journeys stand beside 155 legacy test cases. The comparison is the regression pack as each framework ran it, not a one-to-one mapping.
  • Failed journeys finish early. 734 of the 2,075 Playwright steps were skipped after a failure, so measured times are shown together with a projection for the ENTS pack.
  • Run conditions differ. The legacy builds ran overnight on Bamboo; the Playwright run shown here was started from a laptop on Chrome. The nightly Jenkins runs on OpenShift use the same code.
  • Modernised Selenium has code counts only. No full-run timing was recorded for that stage, so it appears in the approach comparison and not in the run-time charts.
  • Sources. Legacy run time, test-case counts and pass rates come from three Allure build summaries (Builds 7, 153 and 235). Code counts come from the framework comparison of June 2026. Playwright figures come from the BISS / ENTS execution report of 19 November 2026. Herd numbers, logins and farmer details are left out of this dashboard.
